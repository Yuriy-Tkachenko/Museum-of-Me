# Security — MVP

## Включение защиты

1. Применить все три миграции из `supabase/migrations` по порядку, затем развернуть приложение. Вторая миграция закрывает прежние обходы через Supabase API; одного обновления приложения недостаточно.
2. Указать `NEXT_PUBLIC_SITE_URL` (точный HTTPS origin), `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, серверный `TURNSTILE_SECRET_KEY` и случайный `SECURITY_SECRET` длиной минимум 32 символа. Генерация секрета: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Секрет должен совпадать на всех экземплярах приложения.
3. В Cloudflare разрешить только используемые hostname виджета. Без ключей, доступной проверки или таблицы лимитов отправка закрыта; обхода для production нет. Service Role и секреты не должны иметь префикс `NEXT_PUBLIC_`.

## Принятые решения

- **Turnstile:** обязательная серверная Siteverify-проверка `success`, точного `hostname` и `action=submit_exhibit`, таймаут 8 секунд. Токен одноразовый, после попытки виджет сбрасывается. [Документация Cloudflare](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).
- **Rate limiting:** атомарные счётчики в существующем PostgreSQL, общий учёт между процессами/перезапусками, очистка старых записей небольшими порциями. Redis не требуется. Ответ `429` содержит `Retry-After`; отказ БД возвращает `503`.

| Операция | Идентификатор и лимит | Общий бюджет |
| --- | --- | --- |
| Создание музея | Проверенный `auth.getUser().id`: 5/час | 200/час |
| Отправка экспоната | Подписанная cookie: 10/час; приглашение: 150/час | 300/час |
| Pexels | Подписанная cookie: 20/мин; действующее приглашение: 60/мин | 500/час |
| Просмотр приглашений / генерация постера | Общий лимит | 1000/мин / 120/мин |

- **Идентичность:** cookie содержит случайные 256 бит, срок действия и HMAC; `HttpOnly`, `SameSite=Strict`, в production `Secure` и `__Host-`. В БД записываются HMAC-идентификаторы. IP и присланные `X-Forwarded-*` не используются как доказательство личности. Очистка cookie обходит ограничение конкретного посетителя; лимиты приглашения/общие бюджеты и Turnstile сохраняются. Это не гарантия «один человек — одна отправка».
- **RLS / dashboard:** данные музея и приглашения читает только владелец. Экспонаты недоступны даже владельцу до reveal; для прогресса служит отдельный счётчик. Статус, порог, приглашения и экспонаты нельзя менять через browser Supabase API. Идентификаторы повторной отправки и посетителя не доступны браузерному SQL-роли. Dashboard сам проверяет пользователя, независимо от middleware.
- **Service Role:** только `server-only` модули. Создание музея получает владельца из проверенного пользователя; запись экспоната — из проверенного приглашения. RPC разрешены только `service_role`, имеют фиксированный пустой `search_path`, не строят динамический SQL. Публичные чтения проверяют статус до запроса экспонатов. После reveal музей доступен всем по slug, включая постер.
- **Повторы / гонки:** музей, профиль и приглашение создаются транзакционно; конфликт slug откатывает всю операцию. Отправка имеет UUID и уникальность по приглашению + UUID / посетителю. Блокировка строки музея сериализует вставку, проверку вместимости и reveal, включая разные приглашения. Двойной клик блокируется в UI; серверная защита работает самостоятельно.
- **Invite token:** новые токены — `gen_random_bytes(32)` (256 бит). Прежние случайные UUID-токены сохранены; слабые/demo-токены миграция заменяет. Новые ссылки видны владельцу в dashboard. Неизвестные/истёкшие приглашения не раскрывают содержимое; токены исключены из Referrer и индексации страниц. Не сохраняйте URL приглашений в аналитике и логах прокси.
- **Файлы / MIME:** максимум 4 MiB на файл и ограничение реально прочитанного HTTP body, включая chunked encoding. Сервер декодирует JPEG/PNG/WebP через Sharp, сверяет определённый формат с MIME, отклоняет SVG, повреждённые/анимированные изображения и изображения более 25 млн пикселей. Повторное кодирование в WebP до 1600×1600 удаляет метаданные. Имя и путь задаёт сервер. HEIC допускается только как исходник браузерного преобразования в WebP.
- **Storage:** bucket приватный, браузерные операции запрещены дополнительной restrictive policy. Ссылки на загрузки подписываются на 5 минут только после reveal. Старые публичные URL преобразуются в приватные ссылки при чтении; старые файлы следует проверить/перекодировать отдельно. Ранее скачанные копии отозвать невозможно; при переходе с публичного bucket нужно очистить прежний CDN-кэш. Незавершённая загрузка удаляется; при неопределённом результате SQL-запроса файл сохраняется приватным для последующей сверки, чтобы не удалить файл уже принятого экспоната.
- **XSS / SSRF / SQL injection:** title/caption выводятся как React-текст, без HTML-интерпретации. Pexels URL разрешены только для HTTPS `images.pexels.com/photos/...`, включая чтение старых записей перед генерацией постера. Произвольные URL, SVG/data/javascript и локальные адреса не принимаются. Запросы используют параметры Supabase/RPC. Поля ограничены Zod и DB constraints: имя 80, музей 100, title 120, caption 300, URL 2048 символов. Для существующих строк новые ограничения добавлены `NOT VALID`: они проверяют все новые/изменяемые строки; старые данные следует проверить перед `VALIDATE CONSTRAINT`.
- **Route Handlers / headers:** same-origin проверка POST, ограниченные тела запросов, проверка типов/дубликатов полей, обобщённые ошибки без секретов. OAuth redirect ограничен локальными маршрутами. CSP использует новый nonce на каждый ответ, страницы динамические; `unsafe-inline` разрешён только стилям, `unsafe-eval` — только в development. Включены `nosniff`, запрет iframe, `no-referrer`, Permissions Policy, HSTS в production и запрет кэширования чувствительных ответов.

## Проверки и границы

Аналитика Plausible включается только через ENV. В события не попадают invite token, slug, email, тексты экспонатов или auth ID; URL заменяются общими маршрутами. Для группировки используется отдельный случайный UUID музея. Учтены DNT/GPC, без провайдера запросов и аналитического хранилища нет. Определения событий и четырёх воронок — в README.

Браузер сжимает исходное фото перед отправкой; сервер принимает максимум 4 MiB, чтобы multipart-запрос помещался в лимит Vercel. Генератор постеров получает только разрешённые Pexels URL или подписанные URL своего Storage, запрещает редиректы, ограничивает время/размер и перекодирует изображения в JPEG перед рендерингом. При ошибке показывает безопасную заглушку.

`npm run test:e2e` проверяет полный сценарий на desktop и mobile с настоящей локальной Supabase, включая приватный файл до reveal, автоматическое открытие музея, PNG и события аналитики. Только в тестовом процессе внешние ответы Turnstile/Pexels заменяются фикстурами; production-приложение не содержит обхода CAPTCHA.

`npm run test:security`, `npm run test:security:db` (локальный Docker), `npm run lint`, `npm run typecheck`, `npm run build`, `npm audit`. DB-тест создаёт одноразовый PostgreSQL с минимальными схемами Supabase, проверяет RLS, права RPC/Storage, миграцию токенов, rollback, дубликаты и параллельные запросы. Рабочую БД он не затрагивает.

Настоящие ключи Cloudflare и Supabase нужны для финального end-to-end теста на развёрнутом окружении: отправка с виджетом, запрет повторного токена, приватный файл до reveal и его доступность после. При публикации также ограничьте размер тела/время запроса на хостинге. Общие бюджеты MVP могут временно ограничить всех посетителей при атаке; они не заменяют защиту хостинга от объёмного DDoS.

Основание для политики доступа: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [приватные bucket](https://supabase.com/docs/guides/storage/buckets/fundamentals).
